# HypoDJ product stance

Status: active
Created: 2026-10-06
Updated: 2026-10-06 (surface naming: djc / dj)
Audience: Guilherme (and agents working this tree)

This page locks what the product is, what parity means, what an egui port may
touch, and the first depth-first drill. It derives from the repo README ethos,
`CLAUDE.md`, `docs/design`, `docs/decisions`, and Familiar Tools OS framing
(`~/familiartools/README.md`, `collaborator-one-pager-2026-09-27.md`). It does
not invent a second north star.

## Fundamentals

**HypoDJ is the DJ underneath.** The name is the Roman hypocaust: heat from
below, clients in the warm room. One Rust daemon speaks MPD text to clients and
is itself an OpenSubsonic client plus mpv player. Truth lives in the daemon and
in typed Plan IR. Clients do not own audio. Clients do not invent outcomes.

**Human-native listening, not another feed.** Driving music should feel like
speech and physical controls: say what you want in plain words, get a validated
plan echoed back before it arms, never a surprise. Pause, resume, and skip fade.
Volume moves like a fader, not a step. Continuation matches the shape of what is
already playing (album-shaped walk when the queue is a record). Marks keep the
sound you heard. The offline mirror and tape are substrate, not spectacle.

**Familiar Tools organ, not a parallel brand.** Familiar Tools is an OS for how
to live with computers: remember what matters, listen when spoken to, run the
boring loops, hand attention back. Most tools capture attention. These hand it
back. HypoDJ already lives under that tree and org. Its listening ethos (startle
safe, echo before arm, honest filenames, surfaces that earn a line only if the
user can act) is the same grain. Do not invent Launch ceremony. Do not pretend
the OS README already lists every organ; the tree is the membership.

**Capability core over clever shells.** Deterministic player, queue, and Subsonic
select sit under Plan IR. NL (rules-first, optional local model) only ever emits
a validated plan. `subsonic.rs` is the only wire-type blast radius. Shared client
code (`hypodj-client`) owns verb-vs-NL routing and the NL handshake. Thin shells
must not grow a second brain.

## Locked stance

### (a) Shared-core multi-surface name

The product name is **HypoDJ**. The daemon binary is `hypodj`. Product surface
names (Guilherme, 2026-10-06):

| Product surface | Intended invoker | Role |
| --- | --- | --- |
| Daemon (truth) | `hypodj` | MPD server, Plan IR, mpv, Subsonic, tape, store |
| CLI | **`djc`** | Verbs + NL over MPD/TCP; primary audience = AI agents / LMs |
| GUI | **`dj`** | Graphical listening shell (egui when a graphical session exists) |
| TUI fallback | **`dj`** (no graphical session) | Same product surface as GUI; opens the terminal shell when there is no display |

`dj` is one product surface with two presentations: egui/GUI when a graphical
session is available, TUI when it is not. Do not treat TUI and egui as separate
products. Do not invent a second umbrella.

**`dj` falls back to `djc` when the invoker is not a listening session.** If the
user passes arguments or commands, or if `dj` is run programmatically /
non-interactively (piped stdin, non-TTY, agent/script argv), `dj` hands off to
`djc` rather than opening the TUI or egui shell. Interactive, no-args `dj`
still chooses egui when a graphical session exists, else TUI.

**On-disk crates and binaries today (do not invent renames in code from this
page):**

| Crate path / package | Binary name today | Maps to product surface |
| --- | --- | --- |
| `crates/hypodj-daemon` (`hypodj-daemon`) | `hypodj` (+ `probe`, `play-probe`) | Daemon (matches) |
| `crates/hypodj-cli` (`hypodj-cli`) | `dj` | Intended product name: **`djc`** (CLI). Binary still named `dj`. |
| `crates/hypodj-tui` (package name `dj-gui`) | `dj-gui` | Intended product name: **`dj`** (GUI / TUI fallback). Binary still named `dj-gui`. |
| `crates/hypodj-client` (`hypodj-client`) | (library) | Shared client |

Product intent and current binary names diverge for the CLI and the listening
shell. This stance locks the product names (`djc`, `dj`). Renaming binaries or
crates is a separate eng change; this page does not authorize it.

### (b) Listening-experience parity

`djc`, `dj` (TUI fallback), and `dj` (egui when graphical) must produce the
**same listening outcomes** for the same intent. Same fade semantics. Same
echo-before-arm. Same queue and now-playing truth. Same mark / heard / radio /
store meanings. Chromes may differ; the deck may not. If a surface cannot
express an outcome privately owned by another surface, that is a design bug in
the shared contract, not a license for the pretty shell to fork behavior.

Parity is proven against the daemon, not by matching screenshots. Stock MPD
clients (ncmpcpp, mpc) already prove the protocol surface; HypoDJ shells prove
the intent surface (verbs + NL + heard).

### (c) CLI primary audience

`djc` is for **AI agents and LMs first**, humans second when they want a sharp
pipe. That is why verb routing is pedantic: bare verbs and one expected scalar
only; multi-word phrases go to NL so "play something calmer" never silently
becomes a wrong queue play. Stable verbs. Echo before arm. Result lines that say
what actually happened. Same outcomes as `dj` (TUI or egui) for the same plan.
Agents get a contract they can script; humans get honesty. If a change makes the
CLI prettier for humans and less reliable for agents, reject it.

Until the binary rename lands, the shipped CLI invoker on disk is still `dj`
from `hypodj-cli`. Prefer speaking product language (`djc`) in stance and
planning; when documenting exact shell commands against today's tree, name the
binary that actually exists.

## egui port: scope and non-goals

egui is a **major intervention on the shared design**, not a parallel jukebox.
It is the graphical presentation of the **`dj`** product surface (TUI remains
the no-display fallback of that same surface).

**In scope**

- A shell over MPD/TCP and `hypodj-client` (or the same seams), no libmpv in the
  GUI process.
- Listening parity with `djc` and with `dj` TUI fallback for verbs, NL
  echo-before-arm, queue, now-playing, mark/heard, radio, store status the user
  can act on.
- Physical-feeling controls that match daemon fade and volume semantics.
- Proving each outcome against a silent probe daemon (`audio = null`) before
  claiming it works.

**Out of scope (non-goals)**

- A second product name, brand track, or Launch page.
- Owning playback, Plan IR, Subsonic, tape, or store logic in the GUI crate.
- Replacing the TUI fallback as the no-display shell, or freezing TUI work to
  fund chrome.
- Feature lists that outrun parity: visualizers, layouts, and polish land only
  after the shared outcome they decorate already matches.
- Touching David / RealityMaker / VPS work (David freeze).
- Inventing eng ceremony (roadmap theater, invent PRs for show).

If egui needs a capability the daemon cannot express, the fix is daemon + Plan
IR (and then every surface), not a GUI-only side door.

## Parity rules (djc / dj TUI / dj egui)

1. **One truth.** Daemon state and Plan IR decide what happened. Shells display
   and request; they do not reinterpret.
2. **Echo before arm.** Natural language never mutates the deck until the
   validated plan is shown and confirmed. Agents and humans get the same gate.
3. **Same verbs, same outcomes.** A control that exists on more than one surface
   must mean the same thing and leave the same queue/now-playing/volume/mark
   trail.
4. **No audio in the shell.** Clients stay pure MPD/TCP. Probe and test daemons
   stay silent (`HYPODJ_AUDIO=null`, store not pointed at the live mirror).
5. **Earn the line.** Status text appears only if the user (or agent) can act on
   it. Forensics stay behind opt-in surfaces (`djc store frontier`, logs; today
   still invoked as `dj store frontier` on the CLI binary).
6. **Shape follows listening.** Continuation and related behavior derive from
   the deck, not from a sticky GUI mode that can drift.
7. **Refuse silent wrong action.** Pedantic routing beats clever guesswork. If
   intent is ambiguous, go to NL or ask; never half-apply.

## First DFS drill

**Depth over breadth:** prove one listening outcome end to end, compress the
contract, stop.

Drill: pick a single NL phrase that is already real on the CLI (for example
"play something calmer" or an equivalent rules-backed plan). Against a
**silent** probe daemon, run echo → confirm → arm on the CLI (`djc` in product
terms; today's binary `dj` from `hypodj-cli`) and on the TUI fallback of `dj`
(today's binary `dj-gui`), and show that queue and now-playing match. Write the
minimal parity checklist that result implies (handshake fields, result line, no
shell-side reinterpretation). That checklist is the **egui entry gate**: no egui
pixel work until the graphical `dj` presentation can pass the same drill on the
same silent daemon.

Done means: one shared outcome, one written gate, zero new surfaces invented.
Not done means: a feature tour, a mock UI, or a second plan language.
